# Вклад задач в репозиторий (community tasks)

Любой пользователь может добавить свою задачу в общий банк ITInterview.
Задача попадает в репозиторий **одним новым файлом** — регистрация в коде не
нужна: сборка банка (`backend/app/seed/tasks_data.py`) автоматически подхватывает
все модули `bank_*.py`, а seeder идемпотентен по slug (новые задачи добавляются
в БД при старте, существующие не трогаются).

## Как это работает

1. Установите систему (`./install.sh`) и войдите в админку.
2. Создайте задачу во вкладке «Задачи» (+ Новая задача) или возьмите существующую.
3. Нажмите **📤 Вклад** в строке задачи → укажите имя автора →
   «Проверить и сгенерировать». Система:
   - проверяет требования (паттерн, sample-тест, эталонное решение);
   - прогоняет эталонное решение **в песочнице** по всем тестам задачи;
   - генерирует файл `bank_community_<author>_<slug>.py` с кодом и инструкцией.
4. Сохраните файл в свою копию репозитория:
   `backend/app/seed/<имя файла>`.
5. Отправьте PR:

   ```bash
   git checkout -b community-task-<slug>
   git add backend/app/seed/<имя файла>
   git commit -m "Add community task: <название>"
   git push origin community-task-<slug>
   # затем создайте Pull Request на GitHub
   ```

Альтернатива без веб-интерфейса (CLI, при запущенной системе):

```bash
python scripts/export_task.py --slug <slug> --author <имя> \
    --out backend/app/seed/bank_community_<имя>_<slug>.py
```

## Формат файла

Файл обязан экспортировать `TASKS: list[dict]`:

```python
TASKS = [
    {
        "slug": "community-ivanov-my-task",      # уникален среди всего банка!
        "title": "Название задачи",
        "legend": "Сюжет + разделы «Формат ввода» и «Формат вывода». Примеры не пишем — они берутся из sample-теста.",
        "pattern": "dp",                          # один из существующих паттернов
        "level": "junior",                        # junior | middle | senior
        "hints": ["Подсказка 1", "Подсказка 2"],
        "tests": [
            {"name": "sample", "stdin": "...", "expected_stdout": "...", "sample": true},
            {"name": "t2",     "stdin": "...", "expected_stdout": "...", "sample": false}
        ],
        "reference_solution": "# эталонное решение (python), читающее stdin и пишущее stdout",
    }
]
```

## Требования к вкладу

- **Эталонное решение обязательно** и должно проходить все тесты в песочнице
  (проверяется автоматически при экспорте; формат — программа на Python 3,
  stdin/stdout).
- **sample-тест обязателен** (`"sample": true`) — он показывается студенту как
  пример из условия; минимум один скрытый тест тоже нужен.
- **slug уникален** среди всего банка задач (конвенция: `community-<author>-...`).
  При совпадении seeder оставит первую встреченную задачу.
- **Паттерн** — один из существующих (два указателя, скользящее окно, DP и т.д.);
  новые типы паттернов во вкладах пока не поддерживаются.
- В легенде не пишем примеры — они отображаются автоматически из sample-теста.

## Проверки перед PR

```bash
make test          # backend: 69 pytest-тестов (песочница и LLM — фейки)
cd frontend && npx tsc --noEmit && npm run build   # типизация + сборка
```

Для задач из банка дополнительно: эталонное решение должно проходить все тесты
в реальной песочнице (`scripts/validate_seed.py` после `docker compose --profile runner build`).

## Безопасность

- Код студентов и эталонные решения исполняются только в Docker-песочнице:
  `--network none`, лимиты CPU/RAM/pids, read-only rootfs, таймаут.
- Вклад принимается **только после ревью** — проверяйте корректность эталона и
  тестов перед merge (PR с одним файлом легко читается).
