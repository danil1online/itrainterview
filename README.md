# ITInterview — тренажёр алгоритмических собеседований

Web-система подготовки выпускников ИТ-специальностей к алгоритмическим
собеседованиям (FAANG/Big Tech style). Задачи банка построены на классических
паттернах (два указателя, скользящее окно, префиксная сумма, бинарный поиск,
DFS/BFS, DP, greedy, куча, trie, Евклид, Флойд) — ИИ-помощник генерирует новые
легенды, проверяет решения и объясняет ошибки.

## Возможности

- **Студент**: регистрация/вход (JWT), раздел **«Теория»** — по каждому из 13
  паттернов: подробное введение (с объяснением O-обозначений «для новичка»),
  сравнение малоэффективного и эффективного решений, типы задач; 2 примера с
  решениями на Python, Java, C++ и JavaScript (с подробными комментариями);
  ссылки на открытые источники + раздел **«Литература»** (Кнут, Кормен,
  Клейнберг/Тардос, Дасгупта и др. — PDF-ссылки); банк задач (45 задач: Junior 15 /
  Middle 16 / Senior 14) с фильтрами по паттерну и уровню; редактор Monaco
  (Python 3, Java 17, C++17, JavaScript/Node 20); «Запуск (тесты из условия)» —
  отладка на примерах без учёта в статистике; «Отправить на проверку» — все
  скрытые тесты, результат идёт в прогресс/статистику, при провале — разбор от ИИ;
  чат с ИИ-помощником (режимы «наводящие подсказки» / «объяснение ошибок»; видит
  результат последнего запуска со stderr и предупреждает, если код запущен не в том
  интерпретаторе); кнопка «🎲 новая легенда от ИИ» и **«Сгенерировать новый
  комплект задач»** — персональный набор новых сюжетных легенд для всего банка
   (логика и тесты не меняются, корректность гарантирована; опционально единая тема).
- **Резюме и карьера**: форма резюме с подсказками «откуда взять» и автозаполнением
  полей-заглушек (152-ФЗ: персональные данные не хранятся, в DOCX они выделены красным —
  студент заменяет их в скачанном файле); экспорт в .docx; детерминированная рекомендация
  должности по навыкам; **«Рекрутёр»** — LLM-скрининг-собеседование после заполнения резюме
  + рекомендации по итогам.
- **Вайб-Кодинг**: тренажёр работы с компактной ИИ-моделью (Qwen 3B, 32k): трёхпанельный
  экран (задача | диалог с моделью | Monaco + «Запустить тесты»), 4 типа задач
  (исправление бага, генерация юнит-тестов с проверкой мутантами, атомарный рефакторинг
  с AST-гейтом вложенности, генерация по строгому контракту). Модель не видит редактор —
  тренируются декомпозиция, точечный контекст и ревью ответов ИИ. Оценка: тесты (50) +
  итерации диалога (20) + качество промптов (15) + гигиена кода (15).
- **Песочница**: каждый запуск — отдельный Docker-контейнер без сети, с лимитами
  CPU/RAM/pids, read-only rootfs, таймаутом; компиляция Java/C++ тоже в контейнере.
  Одновременных контейнеров не больше лимита (по умолчанию `min(CPU, 8)`, hot-настройка
  `sandbox_max_concurrent`) — при наплыве запуски ждут слот, а не убивают хост.
- **LLM-очередь**: все обращения к модели (чат помощника, рекрутёр и рекомендации,
  вайб-кодинг, ретайт, «новый комплект», разбор проваленных сабмитов) уходят в одну
  FIFO-очередь на базе БД: job переживает рестарт бэкенда, при сбое модели — ретраи
  с backoff (5/15/45с ×3), фронтенд поллит статус и показывает «Модель занята — вы №N
  в очереди». Долгоживущие HTTP-соединения не держатся, поэтому задержки одиночной
  компактной модели при 20–30 студентах не роняют nginx/браузер. Конкурентность —
  hot-настройка `llm_max_concurrent` (по умолчанию 1).
- **ИИ-помощник**: любой OpenAI-совместимый интерфейс (llama.cpp и т.п.).
  Ретайт легенд (JSON с валидацией), автоматический разбор проваленных сабмитов,
  Socratic-чат без готовых решений.
- **Администратор**: пользователи (блок/роль/сброс пароля), CRUD задач +
  ИИ-ретайт (форма с подсказками: адрес задачи/slug, формат JSON тестов),
  просмотр всех отправок с кодом и разбором, статистика по паттернам /
  уровням / дням, топ решателей, экспорт CSV, горячие настройки системы
  (URL/модель/ключ LLM, лимиты песочницы, вкл/выкл саморегистрации).

## Быстрая установка (Ubuntu 20.04+)

```bash
git clone <репозиторий> itrainterview && cd itrainterview
./install.sh
```

Установщик интерактивно спросит:
1. **URL OpenAI-совместимого интерфейса ИИ-помощника** (по умолчанию
   `http://192.168.2.83:8080/v1`) — проверит доступность через `GET /models` и
   автоматически подставит имя модели (например, `qwen2.5-3b-instruct-q4_k_m.gguf`);
2. **порт веб-интерфейса** (по умолчанию **7777**);
3. **email/пароль первого администратора**.

Далее: установка Docker при отсутствии, сборка образов (backend, frontend,
раннеры python/node/java/cpp), `docker compose up -d`, миграции Alembic,
seed банка задач, создание админа, smoke-тест. Итог: `http://<сервер>:7777`.

Неинтерактивно (CI):

```bash
./install.sh --non-interactive \
  --llm-url http://192.168.2.83:8080/v1 \
  --port 7777 --admin-email admin@example.com --admin-password 'secret'
```

Управление: `make up | down | build | logs | migrate | seed | test`.
Удаление: `./uninstall.sh [--purge]`.

## Вклад задач (community)

Система публично пополняемая: любая задача из админки экспортируется в один
самодостаточный файл `backend/app/seed/bank_community_<author>_<slug>.py`
(кнопка «📤 Вклад» или `scripts/export_task.py`). Перед генерацией эталонное
решение проверяется песочницей по всем тестам. Файл подхватывается автоматически
(автосборка всех `bank_*.py`, seeder идемпотентен по slug) — вклад = один новый
файл в PR, регистрация в коде не нужна. Подробности и требования: CONTRIBUTING.md.

## Архитектура

```
itrainterview/
├── install.sh / uninstall.sh / Makefile     # установка на Ubuntu-сервер
├── docker-compose.yml                       # db + backend + frontend + runner-* (profiles)
├── infra/nginx.conf                         # :7777 → SPA + proxy /api → backend
├── runner-images/*.Dockerfile               # образы-песочницы: python, node, java, cpp
├── backend/                                 # FastAPI + SQLAlchemy 2 + Alembic
│   ├── app/api/       auth, tasks, runs, assistant, resume, recruiter, vibe, llm_jobs, admin
│   ├── app/services/  llm (OpenAI-compat клиент), llm_queue (FIFO-очередь job'ов),
│   │                  llm_handlers (побочные эффекты job'ов), sandbox (docker SDK + семафор),
│   │                  grading, assistant, skills (навыки резюме), resume_docx, vibe_runner
│   ├── app/seed/      банк из 45 задач по 13 паттернам (junior/middle/senior) + эталоны,
│   │                  vibe_data.py — 8 задач вайб-кодинга; seeder идемпотентен по slug
│   └── tests/         pytest (69 тестов; песочница и LLM — фейки, очередь — настоящая)
├── frontend/                                # React 18 + Vite + TS, Monaco (бандлится локально)
│   │                                        # страницы: Теория, Банк задач, Решение, Статистика,
│   │                                        # Резюме, Рекрутёр, Вайб-Кодинг, Админка; src/theory/ — данные «Теории»
└── scripts/validate_seed.py                 # прогон эталонов всех задач в реальной песочнице
```

**Безопасность запуска кода**: `docker run` на каждый тест —
`--network none`, `mem_limit/memswap`, `nano_cpus`, `pids-limit=128`,
read-only rootfs + tmpfs, пользователь nobody, таймаут с принудительным kill.
Backend монтирует `/var/run/docker.sock` (запуск «brouter-of-sandbox»); в
production сокет стоит ограничить (socket-proxy / rootless docker).

**Банк задач**: формат stdin/stdout; первый тест каждой задачи — пример из
условия (`sample`), остальные скрыты (ожидаемый вывод студенту не отдаётся).
Все эталоны проверены реальной песочницей: `scripts/validate_seed.py`.

## Основные API

| Метод | Путь | Кто | Назначение |
|---|---|---|---|
| POST | /api/auth/register, /login, /refresh | все | JWT access+refresh |
| GET  | /api/tasks?pattern=&level= | студент | список + флаг «решено» |
| GET  | /api/tasks/{slug} | студент | условие + sample-тесты (с учётом персональной легенды) |
| POST | /api/tasks/{slug}/run | студент | прогон sample-тестов |
| POST | /api/tasks/{slug}/submit | студент | скрытые тесты; при провале — `feedback_job_id` (разбор придёт из очереди) |
| POST | /api/tasks/{slug}/retitle | студент | новая легенда от ИИ → job (сохраняется за студентом) |
| POST | /api/tasks/generate-set | студент | «новый комплект»: по job'у на каждую задачу банка |
| POST | /api/assistant/chat | студент | чат-помощник (hint/explain) → job; контекст: код, последний запуск со stderr |
| GET  | /api/resume, PUT /api/resume | студент | резюме (ПДн-заглушки подставляются принудительно); изменение данных сбрасывает историю рекрутёра |
| POST | /api/resume/docx | студент | экспорт .docx (заглушки ПДн — красным) |
| POST | /api/recruiter/chat, GET /history | студент | LLM-скрининг → job; история диалога |
| POST | /api/recruiter/recommendations | студент | рекомендации по итогам → job; повтор без нового диалога — 409 |
| GET  | /api/recruiter/recommendation | студент | последние рекомендации + флаг `fresh` |
| POST | /api/recruiter/reset | студент | сброс истории и рекомендаций |
| GET  | /api/vibe/tasks, POST /tasks/{id}/session | студент | вайб-кодинг: список задач, сессия |
| POST | /api/vibe/sessions/{id}/chat, PUT /code, POST /run | студент | диалог с моделью → job; автосохранение кода; прогон тестов/мутантов + скоринг |
| POST | /api/llm/jobs | студент | прямой сабмит job'а (202) — обычно используют эндпоинты выше |
| GET  | /api/llm/jobs/{id}, /api/llm/jobs?ids= | студент | поллинг статуса/позиции; пакетный статус для комплекта |
| DELETE | /api/llm/jobs/{id} | студент | отмена ожидающей (pending) задачи |
| GET  | /api/admin/users, /tasks, /results, /stats, /export/submissions.csv, /settings | админ | управление и аналитика |
| POST | /api/admin/vibe-tasks, PUT/DELETE /{id} | админ | CRUD задач вайб-кодинга (эталон проверяется песочницей) |

## Конфигурация (`.env`)

`APP_PORT`, `SECRET_KEY`, `POSTGRES_*`, `LLM_BASE_URL`, `LLM_MODEL`
(пусто = автоопределение из `/models`), `LLM_API_KEY`, `LLM_TIMEOUT_SEC`,
`SANDBOX_HOST_DIR` (абсолютный путь на хосте!), `SANDBOX_TIMEOUT_SEC`,
`SANDBOX_MEMORY_MB`, `ADMIN_EMAIL/PASSWORD/USERNAME`, `SEED_ON_START`.
Часть настроек переопределяется «на горячую» в админке (таблица
`system_settings`): URL/модель/ключ LLM, лимиты песочницы и таймаут запроса к
модели, конкурентность LLM-очереди (`llm_max_concurrent`) и одновременных
контейнеров (`sandbox_max_concurrent`), вкл/выкл саморегистрации.

## Режим разработки

```bash
# backend: sqlite + hot reload
cd backend && python -m venv .venv && .venv/bin/pip install -r requirements.txt
DATABASE_URL=sqlite:///./dev.sqlite3 SEED_ON_START=true ADMIN_EMAIL=a@a.ru ADMIN_PASSWORD=secret123 \
  .venv/bin/uvicorn app.main:app --reload
# frontend (proxy /api → :8000)
cd frontend && npm install && npm run dev        # http://localhost:5173
# тесты
cd backend && python -m pytest tests -q
# валидация банка задач песочницей (нужны собранные runner-образы)
SANDBOX_LOCAL_DIR=/tmp/sandbox-work SANDBOX_HOST_DIR=/tmp/sandbox-work \
  python scripts/validate_seed.py
```
